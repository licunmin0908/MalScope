# MalScope 数据库设计

## 1. 设计原则

- **规范化与性能平衡**：高频检索字段（哈希、等级、时间、类型）建索引；异构分析明细使用 JSON 列。
- **可追溯**：所有实体带创建/更新时间；敏感操作单独落审计表。
- **跨库兼容**：开发用 SQLite、生产用 MySQL 8.0，字段类型均取两者交集（`JSON` / `DateTime` / `String` / `BigInteger`）。
- **级联清理**：样本删除级联清理任务、结果、IOC、报告。

## 3. 核心表结构

### 3.1 `samples` 样本表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(36) PK | UUID |
| original_filename | String(512) | 原始文件名 |
| file_size | BigInteger | 文件大小 |
| file_kind | String(16) idx | pe/elf/office/pdf/script/archive |
| md5 / sha1 | String idx | 哈希 |
| **sha256** | String(64) **UK** | 唯一去重键 |
| ssdeep | String(255) | 模糊哈希（变种聚类） |
| imphash | String(32) idx | 导入表指纹 |
| crc32 | String(8) | 校验和 |
| entropy | Float | 整体熵 |
| is_pe / is_signed | Boolean | 属性 |
| signature_subject | String(512) | 签名主体 |
| packer | String(64) | 壳名 |
| threat_level | String(16) idx | malicious/suspicious/clean/unknown |
| risk_score | Integer idx | 0-100 |
| family / tags / description | - | 家族标签与说明 |
| storage_path | String(512) | 密文路径 |
| aes_nonce | String(64) | IV |
| is_encrypted | Boolean | 是否加密落盘 |
| uploader_id / upload_ip | - | 上传溯源 |

索引：`sha256`(唯一)、`md5`、`sha1`、`imphash`、`file_kind`、`threat_level`、`risk_score`、联合索引 `(threat_level, risk_score)`。

### 3.2 `analysis_tasks` 分析任务表

状态机：`pending → running → success | failed | timeout | cancelled`。
字段：`task_type(static/dynamic/full)`、`progress`、`stage`、`celery_task_id`、`started_at/finished_at/duration_ms`、`result_summary(JSON)`。

### 3.3 `static_analysis` 静态结果表

- 头部原文：`dos_header` / `nt_headers` / `optional_header` / `data_directories`(JSON)
- 关键字段：`entry_point`、`image_base`、`compile_timestamp`、`pdb_path`、`rich_header`
- 加壳：`packer_detected` / `packer_name` / `packer_confidence`
- 资源与签名：`resources` / `version_info` / `signature`(JSON)
- 研判：`suspicious_features`(JSON)、`api_risk_summary`(JSON)、`behavior_hints`(JSON)、`risk_score`、`risk_level`

### 3.4 `dynamic_analysis` 动态结果表

- 环境：`sandbox_driver` / `vm_name` / `snapshot` / `guest_os` / `duration_sec`
- 研判：`verdict` / `risk_score` / `behavior_summary`(JSON) / `attck_techniques`(JSON)
- 反逃逸：`evasion_events`(JSON) / `anti_analysis_detected`
- 落地：`dropped_files`(JSON)

### 3.5 `behavior_events` 行为事件表（时间—进程—对象—动作—结果）

| 字段 | 说明 |
| --- | --- |
| timestamp | 事件时间（索引） |
| category | process/file/registry/network/memory/antidebug |
| action | 动作（process_create/registry_set/network_connect…） |
| object | 作用对象 |
| result | 结果 |
| pid / process_name | 归属进程 |
| severity | critical/high/medium/low/info |
| attck_technique_id / attck_technique | ATT&CK 映射 |
| detail | 附加明细(JSON) |

联合索引：`(dynamic_id, timestamp)`。

### 3.6 `iocs` 威胁指标表

唯一性约束通过联合索引 `(value, ioc_type)` 与 `(sample_id, ioc_type)` 支撑；
字段含 `ioc_type`、`value`、`context`、`confidence`、`threat_score`、`source(static/dynamic/intel)`、`is_whitelisted`、`tags`。

### 3.7 `audit_logs` 审计表

`username` / `action` / `resource_type` / `resource_id` / `result` / `ip` / `user_agent` / `detail(JSON)` / `created_at`。

## 4. ER 关系

见 `diagrams/er.mmd`。核心关系：

```
users ─┬─< user_roles >─┬─ roles ─< role_permissions >─ permissions
       └─< samples ─┬─< analysis_tasks ─┬─| static_analysis ─< pe_sections/pe_imports/pe_exports/extracted_strings/yara_matches
                    │                   └─| dynamic_analysis ─< process_nodes/behavior_events/network_flows/file_events/registry_events
                    ├─< iocs ─< threat_intel_records
                    └─< reports
```

## 5. 建表与初始化

```bash
cd backend
.venv\Scripts\python -c "from app.db.session import init_db; init_db()"
```

`init_db()` 会：建表 → 写入 14 项权限与 4 类角色 → 创建默认管理员 → 导入壳特征库 → 载入内置 YARA 规则。

生产环境建议使用 Alembic 做版本化迁移（`alembic init` 后按模型生成 revision）。
