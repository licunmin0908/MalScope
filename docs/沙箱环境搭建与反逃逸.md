# 沙箱环境搭建与反逃逸设计

> 本文档说明隔离沙箱的搭建方法、行为采集机制与反逃逸对抗措施。

---

## 1. 隔离沙箱总体设计

```
宿主机（分析机）                         隔离网络
┌──────────────────────┐        ┌────────────────────────────┐
│ MalScope 后端/Worker │        │  虚拟化客户机 Windows 7/10 │
│  ├ 快照管理          │        │   Guest Agent (agent.exe)  │
│  └ 驱动(VBox/libvirt)│◀──────▶│   样本执行 + 四维行为采集   │
└──────────────────────┘        └───────────┬────────────────┘
                                            │ 全部外联被重定向
                                   ┌────────▼─────────┐
                                   │ INetSim / FakeNet │
                                   │ 模拟 DNS/HTTP/SMTP │
                                   └──────────────────┘
```

**核心原则**

1. **硬件级隔离**：使用 KVM/QEMU 或 VirtualBox，与宿主机内核隔离；
2. **跑一次清一次**：每次分析前 `snapshot restore`，分析后强制关机并再次回滚；
3. **无真实外联**：客户机网络设为隔离网段/内部网络，所有响应由 INetSim 模拟；
4. **最小权限**：客户机内使用非管理员账户运行样本（如需观察提权则另建快照）；
5. **禁外设**：禁用 USB、剪贴板共享、共享文件夹（或只读单向共享）。

## 2. 虚拟机准备（以 VirtualBox 为例）

### 2.1 创建基础镜像

```bash
VBoxManage createvm --name MALSCOPE_WIN10 --ostype Windows10_64 --register
VBoxManage modifyvm MALSCOPE_WIN10 --memory 4096 --cpus 2 --vram 128 \
  --nic1 intnet --intnet1 malscope_lab --nictype1 virtio
VBoxManage storagectl MALSCOPE_WIN10 --name SATA --add sata
VBoxManage startvm MALSCOPE_WIN10
```

### 2.2 客户机内准备

1. 安装 Windows 10（关闭自动更新，禁用 Defender 实时防护以便观察行为）；
2. 安装 Python 3.8+ 或直接部署打包后的 `agent.exe` 到 `C:\malscope\`；
3. 安装常用运行库（.NET、VC++ Redist），避免样本因缺库而直接退出：
   - **推荐安装**：Office、Adobe Reader、7-Zip、常见浏览器（提升样本触发率）；
4. 关闭系统还原、关闭休眠，减少无关事件噪声；
5. 部署 INetSim（Linux 侧）或 FakeNet-NG（Windows 侧）作为模拟服务端。

### 2.3 制作纯净快照

```bash
VBoxManage snapshot MALSCOPE_WIN10 take clean_base --description "纯净基线快照"
VBoxManage snapshot MALSCOPE_WIN10 list
```

此后每次分析前执行：

```bash
VBoxManage controlvm MALSCOPE_WIN10 poweroff    # 确保关机
VBoxManage snapshot MALSCOPE_WIN10 restore clean_base
```

### 2.4 反逃逸预处理（Pre-run 脚本示例）

在启动客户机后、投递样本前执行，用于降低样本的环境识别能力：

```bat
:: 1) 隐藏 VirtualBox 痕迹
reg add "HKLM\SYSTEM\CurrentControlSet\Enum\IDE" /f
:: 删除 VBox 相关服务与驱动
sc delete VBoxService
sc delete VBoxGuest

:: 2) 篡改注册表硬件描述
reg add "HKLM\HARDWARE\DESCRIPTION\System\BIOS" /v SystemManufacturer /d "Dell Inc." /f
reg add "HKLM\HARDWARE\DESCRIPTION\System\BIOS" /v SystemProductName /d "OptiPlex 7080" /f

:: 3) 移除分析工具特征
:: 确保无 Process Monitor / Wireshark / IDA 等窗口

:: 4) 时间加速：设置较短等待窗口（避免样本依靠 sleep 逃避分析）
:: 通过内核侧 hook GetTickCount/Sleep 或缩短 agent 等待时间实现
```

> 说明：Windows 系统级痕迹隐藏涉及驱动层（如使用内核 hook 或 `VirtualBox` 驱动改名），
> 演示环境中可采用"部分隐藏 + 缩短触发窗口 + 提高交互真实度（预装常用软件、生成用户文档）"的组合策略；
> 时间加速即指对 `Sleep`/`GetTickCount` 的加速处理，使延时触发的样本尽早暴露行为。

## 3. Guest Agent 行为采集

`sandbox/guest_agent/agent.py` 在客户机内运行，采用**多线程轮询 + 差分**方式采集：

| 维度 | 采集方式 | 关键字段 |
| --- | --- | --- |
| 进程 | psutil 轮询 + 父子关系推导 | pid/ppid/name/path/cmdline/user/模块/注入标记 |
| 文件 | 目录快照差分（可扩展 ReadDirectoryChangesW） | 动作/路径/新路径/大小/SHA256/自启动/勒索标记 |
| 注册表 | `winreg` 关键键差分 | Run/RunOnce/Services/IFEO/Shell Folders |
| 网络 | `psutil.net_connections` 差分 | 五元组/协议/方向 |

采集结果写入 `C:\malscope\behavior.json`，由宿主机驱动回收。

**打包为 exe（提升隐蔽性与启动速度）**：

```bat
pip install psutil pyinstaller
pyinstaller -F -n agent agent.py
```

## 4. C2 外联捕获与网络诱捕

1. **DNS/HTTP/SMTP 模拟**：INetSim 监听 53/80/443/25/110 端口，对任意域名返回模拟应答；
2. **流量捕获**：宿主机侧 `tcpdump`/`tshark` 抓包，或用 Suricata 做规则匹配；
3. **C2 判定（平台内置启发式，`engines/sandbox/c2_detect.py`）**：
   - 远控常见端口：4444/5555/1337/31337/8080/8443…；
   - HTTP 路径特征：`/gate.php`、`/panel/`、`/c2/`、`/bot`；
   - User-Agent 异常：陈旧 MSIE、curl、python 等非浏览器特征；
   - 域名字符分布熵、元音比例、数字占比 → **DGA 判定**；
   - 高风险 TLD：`.top/.xyz/.tk/.ml/.ga/.gq/.pw/.cc/.onion…`。

## 5. 反逃逸设计（对抗样本的对抗）

| 样本逃逸手段 | 检测/对抗措施 |
| --- | --- |
| `IsDebuggerPresent` 等反调试 | 平台识别并标注为"反调试行为"（ATT&CK T1622）；宿主机侧反反调试（内核重置调试标志/绕过检测 API） |
| 探测虚拟机（注册表/驱动/硬件指纹） | 痕迹隐藏预处理；监控对 `HKLM\HARDWARE`、`VBOX` 字符串的读取行为 |
| 长时间 `Sleep` 后再触发 | 时间加速（hook `Sleep`/`GetTickCount`）、延长分析窗口、多阶段采样 |
| 检测沙箱环境（进程数、内存、CPU 核数） | 提升客户机配置至真实终端水平；预置用户文档与常用软件 |
| 检测分析工具（进程/窗口标题） | 移除非必要工具；使用不显眼名称的采集组件 |
| 需要用户交互才触发 | 预先放置诱饵文档并模拟打开行为；自动化交互脚本 |
| 自删除清除痕迹 | 采集前备份样本；挂钩文件删除 API；标注"自删除行为" |
| 反编译/加壳对抗静态分析 | 静态阶段识别壳与高熵区段并给出脱壳建议；动态阶段绕开静态混淆直接观察行为 |

**设计取舍**：反逃逸本质是"军备竞赛"，平台不追求 100% 绕过，
而是 ①尽可能提高触发率，②**完整记录样本的对抗意图本身**——
识别到反调试/反虚拟机行为，本身就是重要的恶意证据（对应 ATT&CK T1497/T1622）。

## 6. 安全操作规范

1. **绝不在宿主机直接运行样本**，包括"双击看看"这类直觉操作；
2. 沙箱客户机与生产网络**物理/逻辑隔离**，禁止桥接到办公网；
3. 沙箱快照基线只读保存，分析过程不修改基线；
4. 样本传输使用加密通道，样本库加密落盘；
5. 分析完成及时回滚并清理临时明文；
6. 遵守《网络安全法》与相关实验室管理规定，样本仅用于教学与安全研究。

## 7. 本平台驱动的对接方式

`backend/app/engines/sandbox/drivers/virtualbox_driver.py` 与 `libvirt_driver.py`
已实现上述流程的命令封装（快照回滚、投递、执行、回收、关机回滚），配置项：

```ini
SANDBOX_DRIVER=virtualbox      # 或 libvirt / mock
SANDBOX_VM_NAME=MALSCOPE_WIN10
SANDBOX_SNAPSHOT=clean_base
SANDBOX_TIMEOUT=120
SANDBOX_DISABLE_NETWORK=true
```

无虚拟化环境时使用 `SANDBOX_DRIVER=mock`，平台会依据样本特征确定性合成行为日志，
用以演示与联调完整分析链路（结果中明确标注 `sandbox_driver=mock`，不与真实沙箱混淆）。
