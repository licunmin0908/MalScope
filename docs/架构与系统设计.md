# MalScope 架构与系统设计

## 1. 设计目标与约束

| 维度 | 目标 | 约束 |
| --- | --- | --- |
| 定位 | 纯网络安全方向：恶意代码分析、威胁情报、样本研判 | 不做成通用管理系统 |
| 架构 | B/S 四层：前端展示 / 后端引擎 / 沙箱执行 / 数据存储 | 沙箱必须硬件级隔离 |
| 安全性 | 样本不落地明文、平台不执行样本、操作可追溯 | 分析全过程隔离 |
| 可扩展 | 知识库与引擎解耦、沙箱驱动可插拔 | 规则可热更新 |
| 可运行 | 无虚拟机环境也能跑通全流程 | 提供 mock 驱动 |

## 2. 总体架构

见 `diagrams/architecture.mmd`。四层职责：

- **前端展示层**：Vue3 SPA，负责交互与可视化（区段熵、行为时间线、ATT&CK 矩阵、IOC 分布）。
- **后端分析引擎层**：FastAPI 提供 REST 接口与业务编排，核心是三个引擎（静态/动态/情报）+ 样本管理 + 权限审计。
- **沙箱执行层**：与宿主机操作系统隔离的虚拟化客户机，样本仅在此运行，运行后快照回滚。
- **数据存储层**：关系库保存结构化结果，Redis 承载任务队列，加密卷保存样本密文。

## 3. 模块设计

### 3.1 静态分析引擎

```
engines/static_analysis/
├── hashing.py            多算法哈希（含纯 Python SSDEEP 回退）
├── file_type.py          魔数识别与伪装检测
├── pe_parser.py          PE 结构解析、区段熵、Rich 头、TLS、节区重叠
├── packer_detect.py      加壳检测（签名库 + 启发式）
├── imports_exports.py    导入导出表提取与可疑 API 注标
├── strings_extract.py    恶意字符串提取与分类
├── resources.py          资源、版本信息、数字签名校验
├── yara_scanner.py       YARA 规则匹配
├── suspicious_features.py 可疑特征聚合
├── risk_score.py         风险评分模型
└── engine.py             总编排
```

**关键设计决策**

1. **哈希**：SSDEEP 用于同源变种聚类；原生 `ssdeep` 库缺失时回退到内置 spamsum 纯 Python 实现，保证可移植性。
2. **PE 解析**：`PEContext` 封装一次 `pefile` 解析并复用，避免重复 IO；节区熵用香农熵公式计算。
3. **加壳判定**：单一特征易误报，采用**多信号加权**（节区名签名 + 入口点在末节 + 末节高熵 + 导入表极小 + RWX 节区），阈值 45 分判定为加壳。
4. **可疑 API**：知识库维护 16 类 API 能力，命中即映射到 ATT&CK 技术；**能力 ≠ 恶意**，故在评分中单独低权重处理。
5. **评分模型**：特征分两类——
   - 核心证据（加壳、区段异常、可疑字符串 C2、Overlay、文件伪装…）：全权重；
   - 能力画像（导入表 API 类别）：整体封顶 25 分，且不参与"高危强制抬升"。
   该设计有效抑制了对正常软件的误报（如浏览器、加密组件）。

### 3.2 动态沙箱分析引擎

```
engines/sandbox/
├── base.py              驱动抽象 + 模板方法 run_with_driver
├── drivers/
│   ├── virtualbox_driver.py   VBoxManage 编排
│   ├── libvirt_driver.py      virsh + QEMU Guest Agent
│   └── mock_driver.py         无虚拟化环境下的确定性行为合成
├── orchestrator.py      驱动选择、样本投递、日志回收
├── behavior_analyzer.py 行为归一化、ATT&CK 映射、动态评分
└── c2_detect.py         C2 心跳与 DGA 启发式检测
```

**执行契约**：`prepare() → transfer_sample() → execute() → collect_log() → revert()`，
`run_with_driver` 保证无论成功与否都执行 `revert()`，实现"跑一次清一次"。

> mock 驱动依据样本自身特征（提取到的域名/IP、导入能力、静态研判等级）**确定性合成**行为日志，
> 与真实 Guest Agent 输出结构完全一致，使上层分析逻辑无差别复用；测试演示与真实沙箱可无缝切换。

### 3.3 威胁情报引擎

- `ioc_extractor`：从静态/动态结果提取 IOC，内网地址与良性域名降噪；
- `scoring`：IOC 类型权重 + 来源权重 + 上下文线索；样本级多源融合评分（静态/动态/情报）；
- `exporters`：CSV / JSON / STIX 2.1 / OpenIOC 1.1；
- `intel_client`：VirusTotal 查询、MISP 事件推送（无 Key 优雅降级）。

### 3.4 样本管理与权限

- 加密：AES-256-CTR + HMAC-SHA256（Encrypt-then-MAC），支持大文件流式加解密；
- 去重：SHA256 唯一索引，命中即复用；
- 防护：上传校验（大小/扩展名/压缩炸弹/路径穿越），下载二次授权；
- RBAC：14 项权限 / 4 类角色，JWT 携带主体，每次敏感操作落审计。

## 4. 关键数据流

### 4.1 静态分析数据流

样本密文 → 临时解密到隔离目录 → 静态引擎逐模块分析 → 结果落库（含节区/导入/字符串/YARA 明细）→
回写样本摘要 → IOC 提取 → 删除临时明文。

### 4.2 动态分析数据流

样本密文 → 临时解密 → 编排器选择驱动 → 回滚快照 → 投递 → 执行 → 采集 → 归一化/映射/评分 → 回滚 → 落库 → IOC 提取。

## 6. 安全设计

1. **最小权限**：沙箱客户机仅授予样本运行所需权限，禁网、禁外设；
2. **纵深防御**：上传校验 → 加密存储 → 隔离执行 → 二次授权下载 → 全程审计；
3. **失败安全**：任一分析子步骤异常被隔离捕获，不影响整体产出；沙箱异常也会回滚；
4. **可追溯**：所有敏感操作记录操作人、IP、UA、结果与详情。

## 7. 可扩展性设计

- 知识库外置为 `rules/knowledge_base.json`，新增 API 类别/壳特征/字符串规则无需改代码；
- YARA 规则支持运行时增删与启停；
- 沙箱驱动以配置切换，新增虚拟化后端只需实现 `SandboxDriver` 接口；
- 任务队列在 Celery 与进程内线程池之间自动回退，适配不同部署规模。
