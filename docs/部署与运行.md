# MalScope 部署与运行

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.11+（实测 3.13 可用） | 后端运行时 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0+ | 生产数据库（开发可省略，默认 SQLite） |
| Redis | 6+ | 任务队列（可选） |
| 虚拟化 | VirtualBox 7+ 或 KVM/QEMU | 动态沙箱（可选，缺失时用 mock 驱动） |

硬件建议：8 核 CPU、≥32GB 内存、≥1TB SSD、支持 Intel VT-x/AMD-V。

## 2. 本机开发运行（最快路径）

```bash
# 1) 后端
cd backend
python -m venv .venv
.venv\Scripts\activate                     # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env                     # 默认 SQLite + mock 沙箱，开箱即用
.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 2) 前端（另开终端）
cd frontend
npm install
npm run dev                                # http://localhost:5173
```

访问 `http://localhost:5173`，使用 `admin / Admin@123456` 登录。

## 3. 生产部署（MySQL + Redis + Celery）

### 3.1 数据库准备

```sql
CREATE DATABASE malscope DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'malscope'@'%' IDENTIFIED BY '强口令';
GRANT ALL PRIVILEGES ON malscope.* TO 'malscope'@'%';
FLUSH PRIVILEGES;
```

### 3.2 `.env` 关键配置

```ini
DEBUG=false
DATABASE_URL=mysql+pymysql://malscope:强口令@127.0.0.1:3306/malscope?charset=utf8mb4
REDIS_URL=redis://127.0.0.1:6379/0
USE_CELERY=true
SECRET_KEY=<执行 python -c "from app.core.config import generate_secret;print(generate_secret())" 生成>
AES_MASTER_KEY=<32 字节随机密钥的 base64>
SANDBOX_DRIVER=virtualbox
SANDBOX_VM_NAME=MALSCOPE_WIN10
SANDBOX_SNAPSHOT=clean_base
SANDBOX_TIMEOUT=120
```

### 3.3 启动

```bash
cd backend
.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
# 另开终端启动 Celery Worker
.venv\Scripts\python -m celery -A app.workers.tasks.celery_app worker -l info -c 2
```

> **注意**：动态沙箱编排与虚拟化后端需在同一台宿主机上运行，因此 Worker 建议与分析机同机部署。

### 3.4 前端构建与托管

```bash
cd frontend
npm run build       # 产物在 frontend/dist
```

后端 `app/main.py` 会自动检测 `frontend/dist` 并托管前端静态资源与 SPA 路由，
此时仅需暴露后端 8000 端口即可。

## 4. 容器化部署

见 `docker/docker-compose.yml`：

```bash
cd docker
docker compose up -d --build
# 前端：http://localhost:8080
# API：http://localhost:8000/docs
```

> 沙箱虚拟化**不能**在容器内运行，需在宿主机安装 VirtualBox/KVM，
> 容器通过挂载 `VBoxManage` 或 `virsh` 可执行文件与 socket 调用宿主机虚拟化能力。

## 5. 运维要点

| 项目 | 建议 |
| --- | --- |
| 样本存储 | `backend/storage/` 单独挂载加密卷，定期备份 |
| 日志 | `backend/storage/logs/malscope.log` 轮转（10MB × 5） |
| 密钥 | `SECRET_KEY` 与 `AES_MASTER_KEY` 必须固定，变更将导致历史样本无法解密 |
| 沙箱并发 | 单虚拟机串行；并发需按内存配多台沙箱并调度 |
| 备份 | 至少备份 `samples` 表与 `storage/samples` 密文卷（二者必须配对） |
| 安全基线 | 生产环境关闭 `DEBUG`，限制 CORS 来源，启用 HTTPS |

## 6. 常见问题

**Q1：启动报 `ModuleNotFoundError: app.xxx`**
需在 `backend/` 目录下启动，或设置 `PYTHONPATH` 指向 `backend/`。

**Q2：YARA 规则编译失败**
规则文件必须语法合法；本平台已规避 yara-python 在**中文路径**下 `filepath` 打开失败的问题，
统一以读取文本 + `sources=` 方式编译。若仍有报错，检查 `unreferenced string` 等语法问题。

**Q3：动态分析没有真实行为**
确认 `SANDBOX_DRIVER` 与虚拟机配置；若宿主机无虚拟化（如本机演示），
mock 驱动会依据样本特征合成行为日志，便于跑通全流程。

**Q4：上传样本被拒绝**
检查是否触发压缩炸弹防护（条目数/解压后大小/压缩比）或扩展名黑名单。

**Q5：数据库时间比较报 `offset-naive/aware`**
平台已统一处理时区；如自行扩展，注意 SQLite 读回为 naive 时间，需与 UTC 对齐。
